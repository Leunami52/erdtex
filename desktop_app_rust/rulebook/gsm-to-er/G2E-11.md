title = "Derived attributes"

**Rule.** An attribute line whose label has a part in square brackets (*height [measured]*), and an
attribute line between two representable types, **become** derived attributes (`/height`).

**Conditions.**

- A label with brackets: the attribute is named after the label without the brackets.
- A line from a representable type to another (*Birthday* → *Age*) says the second is derived from the
  first: every object type with an attribute line to the first gets the second as a derived attribute,
  named after the line's label without brackets, or after the type.
- If no object type has an attribute line to the first, nothing carries the derived attribute: the line
  is left out, and the report says so.
- The report lists every derived attribute.
- A derived attribute is never chosen as the key (G2E-2).

**Why.** A derived value is computed from others rather than stored. ER marks it with a slash; the
relational schema gives it no column (and a view where its formula is known).

**Examples.**

```gsmd converts
\abstract{person}(0,0){Person}
\representable{bd}(4,1){Birthday}
\representable{age}(8,1){Age}
\representable{h}(4,-1){Height}
\attribute{person}{bd}{born}
\attribute{bd}{age}{[age]}
\attribute{person}{h}{height [measured]}
```

```erd result
\entity{person}(0,0){Person}
\attributes{person}{*Person ID, Birthday, /Age, /height}
```
