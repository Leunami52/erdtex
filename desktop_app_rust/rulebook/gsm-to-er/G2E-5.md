+++
id = "G2E-5"
title = "A multi-valued attribute line to a representable type"
kind = "conversion"
applies = ["multi-valued attribute line", "representable type", "entity type", "relationship type"]
see = ["G2E-6", "G2E-8"]
+++
**Rule.** A multi-valued attribute line from an object type to a representable type **becomes**, by
default, an entity type for the representable type (key *Name*) and a relationship `cn`:`cn` named after
the line's label; or, if chosen, a multi-valued attribute.

**Conditions.**

- One entity type is made per representable type, also when several lines lead to it.
- Without a label, the relationship is named after the representable type.

**Choices.** *Multi-valued: ‹Owner› ‹label› ‹Type›* in the conversion dialog: *Entity type +
relationship* (the default) or *Multi-valued attribute* (`{Language}`).

**Why.** Several values per object can't be one column of a relation. As an entity type of their own
they can be shared and described further (a language spoken by many people); as a multi-valued
attribute they stay with their owner, and the relational schema gives them a relation of their own.

**Examples.**

```gsmd converts
\abstract{person}(0,0){Person}
\representable{lang}(5,0){Language}
\multiattribute{person}{lang}{speaks}
```

```erd result
\entity{person}(0,0){Person}
\attributes[anchor=west]{person}{*Person ID}
\relationship{speaks}(3.2,0){speaks}
\entity{lang}(6.5,0){Language}
\attributes{lang}{*Name}
\link{person}{speaks}{cn}
\link{speaks}{lang}{cn}
```

```gsmd converts pick=attribute
\abstract{person}(0,0){Person}
\representable{lang}(5,0){Language}
\multiattribute{person}{lang}{speaks}
```

```erd result
\entity{person}(0,0){Person}
\attributes{person}{*Person ID, \{Language\}}
```
