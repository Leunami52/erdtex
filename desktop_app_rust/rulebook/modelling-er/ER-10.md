+++
id = "ER-10"
title = "An attribute belongs to another attribute only if that one is composite"
kind = "warning"
applies = ["Chen attribute"]
fix = "Make 'X' composite"
see = ["ER-9"]
+++
**Rule.** A Chen attribute **may** belong to another Chen attribute (as *Street* belongs to *Address*)
only if that one is composite: made of the attributes that belong to it.

**What the program does.** A warning, *"an attribute can only belong to another one if that is
composite: 'X' isn't"*, at the attribute that belongs to the other, with the fix *Make 'X' composite*
(it sets the option `composite` on X).

- "Belongs to" is either `of=` naming the other attribute, or a line between the two.
- Only the attribute the other belongs to has to be composite: marking the part composite says that it
  has parts of its own, and doesn't count.
- `composite` takes no value: `composite=false` is composite too, as the drawing shows it.
- In an attribute list, composite attributes are written with braces (`Address{Street, Town}`), which
  makes them composite by themselves; this rule is about ovals only.

**Why.** Attributes of an attribute only make sense as its parts. Marking it composite says so, and
the relational schema then gives each part a column of its own instead of one for the whole.

**Examples.**

```erd violates ER-10
\entity{person}(0,0){Person}
\attribute[of=person, key]{ssn}(-3,2){SSN}
\attribute[of=person]{address}(3,2){Address}
\attribute[of=address]{street}(6,3){Street}
```

```erd violates ER-10
\entity{person}(0,0){Person}
\attribute[of=person, key]{ssn}(-3,2){SSN}
\attribute[of=person]{address}(3,2){Address}
\attribute[of=address, composite]{street}(6,3){Street}
```

```erd follows
\entity{person}(0,0){Person}
\attribute[of=person, key]{ssn}(-3,2){SSN}
\attribute[of=person, composite]{address}(3,2){Address}
\attribute[of=address]{street}(6,3){Street}
```
