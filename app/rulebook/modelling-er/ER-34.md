+++
id = "ER-34"
title = "A derived or multi-valued attribute can't be a candidate key"
kind = "warning"
applies = ["attribute list", "Chen attribute"]
see = ["ER-1"]
+++
**Rule.** A further candidate key (*Unique* in the attribute table) **must not** be derived or
multi-valued.

**What the program does.** A warning: in an attribute list *"'Age' is derived, so it can't be a candidate
key"* (or *multi-valued*), at the list; for a Chen attribute *"a derived or multi-valued attribute can't
be a candidate key"*.

- In an attribute list, a further candidate key is marked `+Name`, a derived attribute `/Name`, a
  multi-valued one `\{Name\}`; for a Chen attribute, the options `unique`, `derived`,
  `multivalued`.
- Further candidate keys aren't drawn; they become `UNIQUE` in the relational schema's SQL.
- The key itself (`*Name`) isn't checked here.

**Why.** A candidate key identifies each entity by a stored value. A derived attribute isn't stored (it
is computed), and a multi-valued one holds several values per entity, so neither can identify one.

**Examples.**

```erd violates ER-34
\entity{person}(0,0){Person}
\attributes{person}{*SSN, Name, +/Age}
```

```erd violates ER-34
\entity{person}(0,0){Person}
\attributes{person}{*SSN}
\attribute[of=person, unique, multivalued]{email}(3,2){Email}
```

```erd follows
\entity{person}(0,0){Person}
\attributes{person}{*SSN, +Email, /Age}
```
