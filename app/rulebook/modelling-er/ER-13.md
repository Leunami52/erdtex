title = "A cardinality must be understood"
kind = "warning"
applies = ["line"]
see = ["NOT-1", "ER-14"]
+++
**Rule.** The label of a line between a relationship type (or PART_OF) and an entity type **should** be
a cardinality the program understands: n-notation (`1`, `c`, `n`, `cn`), min-max (`(min,max)`), or one
of the older forms of ER-14.

**What the program does.** A warning, *"'x' is not a valid cardinality; use the picker in the
properties panel"*.

- Spaces and letter case don't matter: `( 0 , * )` and `CN` are understood.
- A min-max pair whose minimum is greater than its maximum, such as `(3,1)`, is not understood.
- Free text (`many`, `some`) is not understood, nor are numbers alone other than `1`.
- The picker in the *Element* pane only offers labels that are understood, so this happens when a label
  is typed in a file by hand.

**Why.** The program reads every label: to say what it means in the *Element* pane, to convert between
notations, to check weak entity types and to build the relational schema. A label it can't read stops
all of that for the relationship, silently, unless it is reported.

**Examples.**

```erd violates ER-13
\entity{student}(0,0){Student}
\attributes[anchor=west]{student}{*Student Id}
\relationship{attends}(4,0){attends}
\entity{course}(8,0){Course}
\attributes{course}{*Course Id}
\link{student}{attends}{many}
\link{attends}{course}{cn}
```

```erd violates ER-13
\entity{student}(0,0){Student}
\attributes[anchor=west]{student}{*Student Id}
\relationship{attends}(4,0){attends}
\entity{course}(8,0){Course}
\attributes{course}{*Course Id}
\setup{card notation=minmax}
\link{student}{attends}{(3,1)}
\link{attends}{course}{(0,*)}
```

```erd follows
\entity{student}(0,0){Student}
\attributes[anchor=west]{student}{*Student Id}
\relationship{attends}(4,0){attends}
\entity{course}(8,0){Course}
\attributes{course}{*Course Id}
\link{student}{attends}{cn}
\link{attends}{course}{cn}
```
