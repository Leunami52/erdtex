+++
id = "ER-14"
title = "A cardinality should be written in its current form"
kind = "hint"
applies = ["line"]
fix = "Write n (or the form it stands for)"
see = ["NOT-1", "ER-13"]
+++
**Rule.** An n-notation cardinality **should** be written as one of `1`, `c`, `n` and `cn`; older and
symbolic forms are understood but not offered.

**What the program does.** A hint, in one of two forms:

- *"the old form 'x' stands for 'y'"*, with the fix *Write y*, for a label that has an n-notation form:

  | Written | Stands for |
  |---|---|
  | `m`, `k`, `p`, `q`, `N`, `M`, `+`, `1..*`, `1..n`, `1..m` | `n` |
  | `mc`, `nc`, `cm`, `cn` in capitals …, `*`, `0..*`, `0..n`, `0..m` | `cn` |
  | `?`, `0..1` | `c` |

- *"'x' has no n-notation form; (min,max) can express it, written at the other end"*, without a fix, for
  a range in square brackets such as `[2,5]`: n-notation has no form for it, and min-max counts from
  the other end, so the program can't rewrite it in place.

Nothing is rewritten unasked: the fix changes the label only when chosen (also with *Fix all*).

**Why.** One form per meaning keeps diagrams easy to read and compare: `n` and `m` say the same, and a
reader shouldn't have to wonder whether they differ.

**Examples.**

```erd violates ER-14
\entity{student}(0,0){Student}
\attributes[anchor=west]{student}{*Student Id}
\relationship{attends}(4,0){attends}
\entity{course}(8,0){Course}
\attributes{course}{*Course Id}
\link{student}{attends}{m}
\link{attends}{course}{cn}
```

```erd violates ER-14
\entity{student}(0,0){Student}
\attributes[anchor=west]{student}{*Student Id}
\relationship{attends}(4,0){attends}
\entity{course}(8,0){Course}
\attributes{course}{*Course Id}
\link{student}{attends}{[2,5]}
\link{attends}{course}{cn}
```

```erd follows
\entity{student}(0,0){Student}
\attributes[anchor=west]{student}{*Student Id}
\relationship{attends}(4,0){attends}
\entity{course}(8,0){Course}
\attributes{course}{*Course Id}

\link{attends}{course}{cn}
```
