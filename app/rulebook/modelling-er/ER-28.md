id = "ER-28"
title = "Depending on itself, the topmost ones depend on none"
kind = "hint"
applies = ["weak relationship type", "weak entity type"]
see = ["ER-25", "ER-27"]

**Rule.** A correct existence dependency of an entity type on itself **may** be drawn; the program then
points out what it means for the topmost ones.

**What the program does.** A hint, *"the topmost 'Chapter' has no 'whole', so it can't depend on one:
the existence dependency only applies to those below another 'Chapter' (deleting a 'Chapter' deletes
those below it)"*. It is information, not a mistake: every correct existence dependency of an entity type
on itself gets it.

- In the relational schema, the one above becomes a foreign key in the dependent's own relation, which
  may be empty (for the topmost), with deletion passed on to those below it.

**Why.** Strictly, a weak entity has exactly one owner; the topmost chapters have none. The program
accepts the diagram because it describes a real dependency that a database can enforce, and says where
the strict reading doesn't hold.

**Examples.**

```erd violates ER-28
\entity[weak]{chapter}(0,0){Chapter}
\attributes[anchor=west]{chapter}{*Title}
\relationship[dependency=E]{in}(5,0){in}
\link[role=part, double, bend left=30]{chapter}{in}{cn}
\link[role=whole, double, bend right=30]{chapter}{in}{c}
```
