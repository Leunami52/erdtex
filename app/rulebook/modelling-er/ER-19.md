+++
id = "ER-19"
title = "A weak entity type should be linked to a weak relationship type"
kind = "warning"
applies = ["weak entity type", "weak relationship type"]
see = ["ER-20", "ER-21", "ER-23", "ER-24"]
+++
**Rule.** A weak entity type **should** be linked to a weak relationship type (a relationship type
marked weak, or with an existence dependency **E** or an identification dependency **Id**) through which
it depends on its owner.

**What the program does.** A warning, *"this weak entity is not linked to a weak (E/Id) relationship"*.

- Where a weak relationship type joins two weak entity types, only the dependent one (the one with the
  double line, ER-23) counts as linked by it; the owner needs a weak relationship of its own to *its*
  owner. While the dependent one isn't chosen yet, both count.
- An entity type is weak when it is marked weak (*Weak entity type* in its *Element* pane, `[weak]`
  in the file); it is drawn with a double border. `weak=false` means not weak, as everywhere.

**Why.** A weak entity type can't be identified, or can't exist, on its own: it depends on an owner. The
weak relationship type is what says on which owner, and how (E or Id). Without it the dependency is
missing from the diagram, and the relational schema can't take the owner's key.

**Examples.**

```erd violates ER-19
\entity{building}(0,0){Building}
\attributes[anchor=west]{building}{*Name}
\relationship{contains}(4,0){contains}
\entity[weak]{room}(8,0){Room}
\attributes{room}{*Number}
\link{building}{contains}{1}
\link{contains}{room}{n}
```

```erd follows
\entity{building}(0,0){Building}
\attributes[anchor=west]{building}{*Name}
\relationship[dependency=Id]{contains}(4,0){contains}
\entity[weak]{room}(8,0){Room}
\attributes{room}{*Number}
\link{building}{contains}{1}
\link[double]{contains}{room}{n}
```
