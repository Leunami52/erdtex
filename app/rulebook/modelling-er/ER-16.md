+++
id = "ER-16"
title = "A relationship type should use the diagram's notation"
kind = "hint"
applies = ["relationship type", "PART_OF"]
fix = "Use n-notation (or min-max notation)"
see = ["NOT-1", "ER-15"]
+++
**Rule.** A relationship type **should** use the cardinality notation the diagram is set to:
n-notation, or min-max with `\setup{card notation=minmax}` (the diagram's *Element* pane, with nothing
selected).

**What the program does.** A hint, *"this relationship uses n-notation, the diagram min-max notation"*
(or the other way round), with the fix *Use …* that converts its labels.

- The fix is offered only where the conversion is exact: not for a relationship of more than two entity
  types (the notations say different things there), nor for a bound that has no form in the other
  notation (such as `(3,*)`).
- A relationship without understood labels uses the diagram's notation by definition and gets no hint.
- A relationship that mixes both notations gets ER-15 instead.

**Why.** Either notation is fine, but one diagram should use one: readers then read every label the same
way round.

**Examples.**

```erd violates ER-16
\entity{student}(0,0){Student}
\attributes[anchor=west]{student}{*Student Id}
\relationship{attends}(4,0){attends}
\entity{course}(8,0){Course}
\attributes{course}{*Course Id}
\link{student}{attends}{(0,*)}
\link{attends}{course}{(0,*)}
```

```erd follows
\setup{card notation=minmax}
\entity{student}(0,0){Student}
\attributes[anchor=west]{student}{*Student Id}
\relationship{attends}(4,0){attends}
\entity{course}(8,0){Course}
\attributes{course}{*Course Id}
\link{student}{attends}{(0,*)}
\link{attends}{course}{(0,*)}
```
