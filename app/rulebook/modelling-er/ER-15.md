+++
id = "ER-15"
title = "A relationship type should not mix the two notations"
kind = "warning"
applies = ["relationship type", "PART_OF"]
see = ["NOT-1", "ER-16"]
+++
**Rule.** All cardinalities of one relationship type **should** be in the same notation: all n-notation,
or all min-max.

**What the program does.** A warning, *"this relationship mixes (min,max) and n-notation, which count
from opposite ends"*, at the relationship type.

- Old forms (ER-14) count as n-notation.
- Lines without a label, and labels that aren't understood (ER-13), aren't counted.
- Converting the relationship in its *Element* pane puts all of its labels into one notation where that
  is exact.

**Why.** The two notations count from opposite ends: in n-notation the label stands at the *other*
entity type, in min-max at the entity type counted. Mixed in one relationship, there is no telling which
label counts which side.

**Examples.**

```erd violates ER-15
\entity{student}(0,0){Student}
\attributes[anchor=west]{student}{*Student Id}
\relationship{attends}(4,0){attends}
\entity{course}(8,0){Course}
\attributes{course}{*Course Id}
\link{student}{attends}{n}
\link{attends}{course}{(1,*)}
```

```erd follows
\entity{student}(0,0){Student}
\attributes[anchor=west]{student}{*Student Id}
\relationship{attends}(4,0){attends}
\entity{course}(8,0){Course}
\attributes{course}{*Course Id}
\link{student}{attends}{n}
\link{attends}{course}{cn}
```
