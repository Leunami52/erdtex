+++
id = "G2E-4"
title = "An attribute line to an object type becomes a relationship"
kind = "conversion"
applies = ["attribute line", "abstract type", "relationship type"]
see = ["G2E-6", "G2E-7"]
+++
**Rule.** A single-valued attribute line from an object type (abstract type or subtype) to another
object type **becomes** a relationship type named after the line's label, with the cardinality `1` at
the target and `cn` at the source.

**Conditions.**

- In n-notation the label stands at the other end: `1` at the target says each source object refers to
  exactly one target object; `cn` at the source says a target may be referred to by any number, also
  none. GSM has no minimum cardinalities, so the conversion assumes 0 where it can't know more.
- A line without a label becomes the relationship *has*.
- A line from an object type to itself becomes a recursive relationship with two lines to the entity
  type (bent apart so that both show).
- A line to an aggregation that becomes an entity type (G2E-9, G2E-10) is converted in the same way.
- Two lines between the same two types in opposite directions are G2E-6.

**Why.** An attribute whose values are objects relates two kinds of objects: in ER that is a
relationship, not an attribute.

**Examples.**

```gsmd converts
\abstract{person}(0,0){Person}
\abstract{city}(5,0){City}
\attribute{person}{city}{lives in}
```

```erd result
\entity{person}(0,0){Person}
\attributes[anchor=west]{person}{*Person ID}
\relationship{lives_in}(3.2,0){lives in}
\entity{city}(6.5,0){City}
\attributes{city}{*City ID}
\link{person}{lives_in}{cn}
\link{lives_in}{city}{1}
```
