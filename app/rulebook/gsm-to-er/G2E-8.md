+++
id = "G2E-8"
title = "A grouping becomes a relationship to the objects it groups"
kind = "conversion"
applies = ["grouping", "component line", "relationship type"]
see = ["G2E-5", "G2E-6", "GSM-12"]
+++
**Rule.** An attribute line to a grouping **becomes** a relationship `cn`:`cn` between the line's source
and the grouping's member type (the type its component line leads to), named after the line's label, or
the grouping's name without one. A grouping that nothing refers to **becomes** an entity type of its own,
with a relationship *contains* to its member type.

**Conditions.**

- A grouping whose member type is a representable type is treated as a multi-valued attribute line to it
  (G2E-5, with its choice).
- A grouping without a component isn't converted; with several, the first is used. The report says so.
- A grouping that is a component of an aggregation becomes such a relationship of the aggregation's
  entity type (G2E-10).

**Why.** A grouping is a set of objects of one type; referring to a set is referring to any number of its
members, which in ER is a relationship to the member type.

**Examples.**

```gsmd converts
\abstract{club}(0,0){Club}
\grouping{team}(4,0){Team}
\abstract{player}(8,0){Player}
\attribute{club}{team}{fields}
\component{team}{player}
```

```erd result
\entity{club}(0,0){Club}
\attributes[anchor=west]{club}{*Club ID}
\relationship{fields}(5.2,0){fields}
\entity{player}(10.4,0){Player}
\attributes{player}{*Player ID}
\link{club}{fields}{cn}
\link{fields}{player}{cn}
```

```gsmd converts
\grouping{team}(0,0){Team}
\abstract{player}(5,0){Player}
\component{team}{player}
```

```erd result
\entity{team}(0,0){Team}
\attributes[anchor=west]{team}{*Team ID}
\relationship{contains}(3,0){contains}
\entity{player}(6,0){Player}
\attributes{player}{*Player ID}
\link{team}{contains}{cn}
\link{contains}{player}{cn}
```
